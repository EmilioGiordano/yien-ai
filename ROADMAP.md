# ROADMAP

The index for agents: where the project stands and what comes next. Each branch updates its own row as its last commit. Rules are in `AGENTS.md`; behaviour in the ERS; engineering in the plan (absolute paths in `AGENTS.md`).

## Target: MVP

A YIEN that Emilio can use for real work on Windows:

- One window. Projects in a sidebar, vertical tabs per project, and split terminal panes per tab, following the prototype `design/prototipo-navegacion.html`.
- Each pane runs a shell or an agent CLI (Claude Code, Codex, OpenCode) through ConPTY, with correct rendering, input (IME, AltGr), copy and paste, and scrollback.
- Panes split, resize, close, swap and get focused by keyboard and mouse. Command palette.
- Claude Code state detection (working / needs you / idle) with the red mark and the attention counter (RN-01, RN-02).
- The layout and sessions survive a restart.
- `yien --test-control` so every feature is validated in the running app (ADR-21).

This is plan milestones M0–M2, the core of M3 and the Claude part of M4. Phase 0 is cut down to the spikes that decide the stack: S2 (ConPTY) and S1 (GPUI), sized to one night.

## Decisions taken on the way
- `feat/divider-drag`: a new `Command::SetDivider { before, after, share }` (PROTO_VERSION 14), not `ResizeSplit`. `ResizeSplit` grows one pane at the cost of all its siblings, so in a three-way split the third pane moves too, and it acts on the pane's own branch, so no pane reaches the divider between a pane and a nested column. `SetDivider` names a divider by any pane on each side; `yien_layout::Tree::set_divider` finds their deepest common branch, refuses children that are not neighbours in that order, and sets only those two flexes to an absolute share of their sum, so a drag never accumulates error and sending it twice is a no-op. Addressed by panes, not by a child-index path, because the protocol tree drops a leaf with no pane and a path goes stale when a pane splits or closes mid-drag.
- `feat/divider-drag`: the UI is the authority on the minimum size. The core refuses a share outside (0, 1) and clamps one closer than `yien_proto::MIN_DIVIDER_SHARE` (0.02) to either end, so a raw `SetDivider` cannot leave a pane at about 0 px; the UI clamps its previews to the same floor, so the preview and the saved layout cannot disagree. The minimum is 10 columns by 3 rows of the tab's terminal cell plus fixed chrome (gutters, border, terminal padding, the pane head: 28 px across, 52 px down, approximate), and it nests: a side split along the same axis needs its tightest pane's minimum over that pane's part, a side split across the axis needs its widest pane's minimum. When a pair cannot hold both minimums the divider does not move.
- `feat/divider-drag`: one drag pattern with the side bars. A shell's name counts only 4 letters in the estimate ("only if room") and shrinks first in the render (`flex_shrink` 1000); an agent's tag counts at full width, so it outlives the folder and the ×.
- `improve/narrow-pane-head`: `program_tag` names an agent pane by its profile id only while its own program runs (`runs_session`), so a stand-in shell after a failed resume, or a pane whose details have not arrived, is never called `claude`. A wide head is unchanged: name, then profile display name.
- `improve/narrow-pane-head`: the head's width is the pane area's last painted width times the pane's layout share, minus gutters and borders; before the first paint it counts as wide. When the pane area changes size, the canvas that watches it schedules a next-frame refresh, so a resize that stops does not leave heads laid out for the old width.

- `fix/claude-shift-enter` (RF-AGE-02, RF-PAN-06): headless captures of Claude Code 2.1.322 and 2.1.323 through the bundled OpenConsole showed that Claude Code sets 9001 itself and pushes kitty flags 5 on the alternate screen, that OpenConsole passes YIEN's Win32 events and `CSI 13;2u` through verbatim (it does not turn the Win32 event into `CSI u`, as `feat/shift-enter-newline` assumed), and that Claude Code ignores the Shift of a Win32 Enter. Shift+Enter with kitty disambiguate is now `CSI 13;2u` before the 9001 check; flags without bit 0 still give the Win32 event. Stale flags stay safe because `KeyModeTracker` empties the main screen's kitty stack at a shell prompt mark (OSC 133 A, ended by BEL or ST, parameters allowed), in byte order inside the tracker so a cut chunk gives the same result; the alternate stack is already emptied on `?1049l`. cmd prompts carry the mark too (`$E]133;A$E` after the folder report); the agent state machine only ends a running turn on it and cmd never starts one, so a cmd pane stays Idle.
