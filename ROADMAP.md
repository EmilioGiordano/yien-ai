# ROADMAP

The index for agents: where the project stands and what comes next. Each branch updates its own row as its last commit. Rules are in `AGENTS.md`; behaviour in the ERS; engineering in the plan (absolute paths in `AGENTS.md`).

## Target: MVP

A YIEN that Emilio can use for real work on Windows:

- One window. Projects in a sidebar, vertical tabs per project, and split terminal panes per tab, following the prototype `design/prototipo-navegacion.html`.
- Each pane runs a shell or an agent CLI (Claude Code, Codex, OpenCode) through ConPTY, with correct rendering, input (IME, AltGr), copy and paste, and scrollback.
- Panes split, resize, close, swap and get focused by keyboard and mouse. Command palette.
- Claude Code state detection (working / needs you / idle) with the red mark and the attention counter (RN-01, RN-02).
- The layout and sessions survive a restart.
- `yien --test-control` so every feature is validated in the running app (ADR-21).

This is plan milestones M0–M2, the core of M3 and the Claude part of M4. Phase 0 is cut down to the spikes that decide the stack: S2 (ConPTY) and S1 (GPUI), sized to one night.

## Decisions taken on the way

Record here what a spike or a branch decided, with the branch name. The plan's spike log in `docs/` holds the details.
- `fix/flaky-session-tests`: tests only. The core race behind RF-SES-04 stays for its own `fix/` branch: a pane reports its session id before spawning (`pane.rs`, `start`), and a `TerminatePane` handled before that report is applied gets its `ended_explicitly` cleared by it (`workspace.rs`, `PaneEvent::SessionId`), so the next start resumes a session the user ended (RN-04). A same-id check alone would leave the fresh-launch case open.
- `fix/ended-session-race`: `ended_explicitly` changes only on the user's commands (terminate sets it, relaunch clears it together with the session id) and on `EndedByUser`; no `SessionId` report clears it any more. Each pane has a launch number the workspace raises on relaunch and hands to the actor; `SessionId` and `EndedByUser` carry it, and the workspace drops those of a launch it replaced. The actor's hook serial could not serve: the workspace never sees it, so it cannot know which launch the user ended. A restore that starts an ended session fresh restores the pane with the mark cleared and no session id, so the new session is resumed next time. `CoreConfig::save_debounce` (default `SAVE_DEBOUNCE`) also stretches the 2 s write cap when longer.
- `fix/ended-session-race`, open: a relaunched Codex or OpenCode pane names no session until a hook reports one, since those profiles get no id before the spawn; a quit before that saves the pane without a session. Follow-ups: terminating a pane restored differently (`kept`: missing folder or unknown profile) saves the kept record, so the end is lost (older than this branch); `Started`, `Exited` and the other lifecycle reports carry no launch number, so one from a replaced launch is still applied.
- `feat/terminal-theme`: the core owns the palette, not the UI. Frames carry resolved RGB, so at paint time a default background cannot be told from a program's truecolor of the same value or from an OSC 11 override, and a sumi-to-washi colour map would recolour those too. The UI sends `ClientMsg::SetTerminalPalette { palette: TerminalPalette::Sumi | Washi }` (`PROTO_VERSION` 10) whenever the theme kind changes (config reload, `system` following the OS, Ctrl+Shift+L, and the first apply at start, since the core starts on sumi). The service keeps the current palette, hands it to every new actor in `PaneSetup` and sends `PaneCmd::Palette` to every pane, hidden ones included; the actor keeps it for the fresh engine each launch builds, so splits, relaunches and the RF-SES-11 shell fallback come up in it. `VtEngine::set_palette` only swaps the palette the engine resolves with, so the screen, the scrollback, OSC 4/10/11 overrides and truecolor stay, and colour queries answer with the new palette. A small enum rather than a full palette on the wire, because `yien-ui` cannot name `yien_vt::Palette`; user palettes would add a variant.
- `feat/terminal-theme`: `Palette::washi()` lives beside sumi in `yien-vt` and uses the light `--term-*` tokens in the roles sumi gives the dark ones: background `--term-bg`, text, cursor and bright white `--term-text`, white `--term-muted`, bright black `--term-faint`, black `--term-raised`, red, yellow and blue `--term-shu`, `--term-ochre`, `--term-ai`. Black is the raised surface in both palettes because Windows' in-box ConPTY paints black as the legacy background and sends inverse text as black on white and bold as bright; with black as dark text, inverse read dark on grey and bold read lighter than normal text (seen in a first capture). Normal colours reach 4.5:1 on the background, bright ones 3:1 (tests in `palette.rs`; black exempt in both); sumi's 19 values are pinned byte for byte. Selection stays the UI's `term_strong`, with `term_text` on it at AA in both themes.
- `feat/terminal-theme`: SGR 2 (faint) fades a third of the way towards the background on a light palette instead of towards black, which on washi read as bold; sumi keeps `Rgb::dim`, so its frames are unchanged.
- `feat/terminal-theme`, review fixes: selected cells keep their own text colour, so washi's grid selection is `#dee2e8` (`--ai-wash` at 14 % over `--term-bg`) instead of `term_strong`, on which red read at 2.19:1 and the bright colours near 1.7:1; on it ANSI 1-6 and 9-14 reach 3.15:1 at the least (bright red 3.31, bright green 3.15, bright yellow 3.26, bright cyan 3.29, the rest 3.6 to 6.1) and the default text 12.35:1, while it stands out from the grid at 1.25:1; sumi keeps `term_strong`. The binary reads `config.toml` before starting the core and starts panes on washi when the file says so (`CoreConfig::with_terminal_palette`), so programs restored before the window's first message draw in it; `system` still waits for the window, which alone reads the OS appearance. The UI remembers the palette the core took and sends it again on the next settings apply or core event batch when a full queue refused it.
- `feat/terminal-theme`, known trade-off: black (ANSI 0) is the raised surface in both palettes, so black text is near invisible on the grid (washi 1.10:1, sumi 1.13:1). Kept on purpose for the in-box ConPTY, which uses black as the legacy background and for inverse text. Follow-up: give index 0 and 7 separate text and background roles (black text readable, black backgrounds raised), revisited when a newer ConPTY is bundled (TBD-05).
